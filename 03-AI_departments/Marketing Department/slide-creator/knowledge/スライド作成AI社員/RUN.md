# RUN.md — セミナープレゼン作成AI社員の動かし方

不慣れな人でも、このフォルダ **だけ** で「登壇セミナー風のHTMLスライド」を社内と同じ品質で作れるようにした手順書です。
迷ったら上から順番にやってください。

---

## 0. このAI社員が作るもの

**登壇（ウェビナー / セミナー / ピッチ）で、声で語りながら見せる16:9のHTMLスライド一式。**

- 配布して読ませる資料ではありません（それは 12 / 13 の担当）。
- 1スライド1メッセージ・ビジュアル主体・黒背景の核心1文・黄色1色アクセント、という
  「07セミナー風」の見た目に固定します。**紫グラデや明朝体の提案資料とは別物**にするのが肝です。

成果物の最小セット:

```
slides/index.html        ← 本体（これを開くとスライドショーが動く）
slides/css07/deck07.css        ← 見た目（07セミナースタイル）
slides/css07/reference-template.css
slides/js07/deck07.js          ← スライド送り＋拡大縮小
slides/img/                    ← 表紙画像・証拠スクショ・ロゴ
brief.md                       ← 前提メモ
story-plan.md                  ← 設計図（どの順で何を話すか・1スライド1行・型ID付き）
review-notes.md                ← 判断理由・次回固定できること
screenshots/final/             ← 全ページのスクショ（目視QA用）
```

---

## 1. 必要なもの（ツール）

| ツール | 用途 | 入れ方 |
|---|---|---|
| AIアシスタント（Claude Code / Codex 等） | 文章・構成・HTML生成・判断 | 既に使っている前提 |
| Google Chrome | 完成スライドのスクショ確認（headless） | 普通にインストールされていればOK |

> 追加の pip / npm インストールは **不要**。HTMLとブラウザだけで完結します。
> （`engine/slide-creator/` の一部スクリプトは Node や画像素材を要求しますが、このセミナーデッキ作成には使いません。）

---

## 2. 用意する入力（あなたが渡す情報）

最低この5つ。足りなければAIが最大10問まで聞いてきます（`MASTER_PROMPT.md` の「最初の10問」）。

1. **セミナーの日程・タイトル**（例: 「90分・無料オンライン / AI社員を1人雇うと、なぜ作業が消えて売上が残るのか」）
2. **誰に何を伝えるか**（対象者と、今日の結論1文）
3. **最後に案内したい商品・サービス**（価格・特典・申込導線＝CTA）
4. **使ってよい実績・証拠素材**（数字、LP/デッキ/メールのスクショ画像など。**事実だけ**。盛らない）
5. **登壇者の自己紹介**（誰が話すか・なぜ話せるか）

画像（表紙ビジュアル・証拠スクショ・ロゴ）があれば `slides/img/` に置いておくと貼れます。

> **表紙の背景**: 見本の `img/seminar-cover.png` は**別セミナーのタイトルが焼き込まれたサンプル**なので流用しない。汎用の **`img/seminar-cover-generic.png`（文字なし・黒×黄・左に文字用余白）** を敷いて、タイトルはHTML側のテキストで載せるのが標準。自分のイベント用カバーがあればそれを使う。
無い場合もAIがブリーフを出すので、後から差し替えできます。

## 3. 実行手順

### Step 1. AIに読ませる（ここが一番大事）

お使いのAIに、このフォルダの次を **この順で** 読ませてください。

1. `SKILL.md`（入口）
2. `MASTER_PROMPT.md`（実行の正本）
3. `knowledge/05-07-output-standard.md`（セミナーデッキの正解基準・固定ブロック）
4. **`engine/07-seminar-style/sample-index.html`（← 完成見本。これを「正解の見た目」にする）**
5. `engine/07-seminar-style/css07/deck07.css`（← 見た目のDNA。配色・タイポ・カードの作り）

> ★ ここがポイント: **新しくHTMLを自己流で書かせない**。
> `engine/07-seminar-style/` の **sample-index.html を雛形にコピーして、中身（文言・画像・会社名）だけ差し替える** よう指示してください。
> css07 / js07 は**改変せずそのまま**使えば、07セミナーの見た目になります。

### Step 2. 構成を先に確定（HTMLより先）

`story-plan.md` で「話す順番」を先に固めます（1スライド1行: 通し番号/一言メッセージ/型ID/固定or新規）。型は固定:

```
表紙 → 自己紹介/権威付け → 本日の流れ → 現状の痛み → 常識の否定 →
理論/方程式 → 中身（使うツール）→ ビフォーアフター → 証拠スクショ →
限界の提示 → 反論つぶし(FAQ) → オファー/価格 → Q&A → 最終CTA
```

章扉（tone-brand）は同じ見た目で揃え、**同型を3枚以上連続させない**（間に別の型を挟む）。

### Step 3. HTMLを組む

`engine/07-seminar-style/sample-index.html` を `slides/index.html` にコピーし、css07/js07/img もコピー。
各スライドは `<section class="xop-slide tone-...">` 内の `.semantic-layer`（固定1920×1080）に
要素を絶対配置するだけ。文言・数字・画像・会社名を自社のものに差し替えます。

- tone は `tone-dark`（黒・核心1文）/ `tone-minimal`（紙・本文）/ `tone-brand`（章扉）の3種。
- 黄色 `#f5d020` は「今すぐ覚える言葉」のハイライト用。多用しない。
- 証拠スクショは白カード `.card-hard`（太枠＋ハードシャドウ）に入れて見切れさせない。

### Step 4. スクショで目視QA（必須）

全ページを1コマンドで自動撮影して、崩れを直します。

```bash
python3 scripts/shoot_all_slides.py slides/index.html
# ページ数を指定したい場合: --count 26 / 保存先を変える場合: --out screenshots/final
# あわせて素材リンクの欠落検査（missing 0 が合格）:
python3 scripts/validate_deck_assets.py slides/index.html
```

> URLの `#1` `#2` … がスライド番号です（`js07/deck07.js` がハッシュで該当ページを表示）。スクリプトはこの仕組みで全ページを順に撮影しています。
>
> **撮影が異常に遅い環境では**（1枚に30秒以上かかる等・他のChromeやセキュリティソフトと競合していることがある）: ①Chromeを全部終了してから再実行 ②`--mode single` で縦長1枚に撮って俯瞰 ③ブラウザで `slides/index.html` を開いて手動で全ページ目視、のどれかで代替してよい。**「全ページを俯瞰して崩れを潰す」ことが必須**で、撮影手段は自由。

チェックする（`knowledge/05-07-output-standard.md` の「スクショQA」）:

- [ ] 文字が枠からはみ出していない / 見出しが意図せず折れていない
- [ ] 画像比率が崩れていない・スクショが見切れていない
- [ ] 同型スライドが3枚以上連続していない
- [ ] 章扉のブランドルールが揃っている / ロゴ位置が揃っている
- [ ] 文字だけのチープなスライドがない（黒背景の意図的な核心1文だけはOK）
- [ ] 最後のCTAが明確

### Step 5. 残すもの

`brief.md`（前提）・`questions.md`（回答と仮定）・`story-plan.md`（設計図）・`source-map.md`（出どころ）・`review-notes.md`（判断理由と次回固定できること）を残します。
完成物だけ出して終わりにしない。

## 4. 成果物（これが出ていれば完成）

- `slides/index.html`（＋ css07 / js07 / img）… ブラウザで開いて矢印キーで送れる
- `screenshots/final/`（全ページ・shoot_all_slides.pyで自動撮影）… 崩れなしを目視確認済み
- `brief.md` / `questions.md` / `story-plan.md`（型ID付き設計図）/ `source-map.md` / `review-notes.md`

> 🎨 **スライド型は100種類**: 既存26型（`engine/07-seminar-style/sample-index.html`）＋拡張74型（`engine/07-seminar-style/template-library/index-ext-a.html`=SEM-27〜63 / `index-ext-b.html`=SEM-64〜100）。ギャラリーをブラウザで開いて選び、該当sectionをコピーして文言差し替え。
> 💡 **スライドの幅を出したい時**: `../_shared/deck-bank/catalog.md`（スライド型カタログ）を開くと、このパックで使える型と見た目の系統が全部一覧になっています。型のHTMLをコピーして文言だけ差し替えるのが、速くて崩れない作り方です。

## 5. 社内と同じ品質を出すコツ

- **見た目は迷わず `engine/07-seminar-style/` を踏襲する。** ゼロからHTML/CSSを書かない。
- **12 / 13 と見分けがつく別物にする。** 紫グラデ・明朝体・本文びっしり＝NG。07は「モノクロ＋黄色1色／黒ウェイト大見出し／黒背景の核心1文」。
- **表紙・自己紹介・実績・章扉・クロージングは固定資産。** 毎回テーマだけ差し替える。新規テーマ部分だけ考える。
- **数字・実績は渡された事実だけ。** 推測で盛らない。
- **画像は比率を壊さない。** 証拠スクショはハードシャドウ白カードに入れて見切れさせない。
- 例え話（比喩）は固定しない。テーマに一番効くものをその都度選ぶ。

---

## 6. 安全（必ず守る）

- 実在の個人名・顧客名・住所・電話・メール（`example.com` 以外）・口座・契約情報を入れない。
- 同梱の完成見本は架空会社「株式会社アイウエオ」で作っています。自社情報に置き換えて使う。
- メール送信・SNS投稿・LINE配信・公開デプロイは **必ず人間が確認してから**。AIは下書き（HTML）まで。
