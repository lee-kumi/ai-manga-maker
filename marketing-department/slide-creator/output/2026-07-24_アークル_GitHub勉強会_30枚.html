概念

そもそも GitHub って何？

ひとことで言うと——
コードを保存・共有・共同作業できる、クラウド上の場所です。

たとえ：Googleドライブの「プログラム＆チーム作業に特化した版」。誰が・いつ・何を変えたかが全部残る。
概念

Git はタイムマシン

  • Git＝ファイルの変更履歴を記録する仕組み（バージョン管理）
  • 「いつでも過去の状態に戻れる」セーブ機能つきの作業
  • 上書き保存で消えて泣く…がなくなる
ゲームのセーブポイントを好きなだけ作れて、いつでもロードできるイメージ。
概念

Git と GitHub の 違い

Git

あなたのPCの中で動く「履歴を記録する道具」。オフラインでも使える。

GitHub

その履歴をネット上に置いて、共有・共同作業できる「サービス」。

Git＝道具、GitHub＝その道具でつくった記録を置くクラウド倉庫。似た名前だけど別物。
なぜ

なぜ AI団体 にGitHubが効くの？

  • コードやプロンプトをチームで共有・改善できる
  • 誰が何を変えたか残るので、共同開発でも壊れにくい
  • 成果物がそのまま「ポートフォリオ（実績）」になる
  • 世界中のAIプロジェクト（OSS）に参加・勉強できる
全体像

2つの場所を行き来する

手元のPC（ローカル） — push → GitHub（リモート）
手元のPC（ローカル） ← pull — GitHub（リモート）
自分のPCで作業 → GitHubへ「アップロード＝push」／ GitHubの最新を「ダウンロード＝pull」。この往復が基本。
準備

まずは アカウント作成

  • github.com にアクセスして「Sign up」
  • メール・ユーザー名・パスワードを登録（学生はメール認証で無料強化あり）
  • ユーザー名は今後ずっと使う「表札」。シンプルなものが◎
GitHub Student Pack を使うと学生は有料機能が無料に。あとで案内します。
用語 1

リポジトリ（repo）＝プロジェクトの箱

  • 1つのプロジェクト＝1つのリポジトリ
  • コード・画像・説明書（README）をまとめて入れる
  • 公開（Public）／非公開（Private）を選べる
たとえ：作品ごとの「フォルダ＋作業ノート」。アークルのプロジェクトごとに1箱つくる。
用語 2

コミット（commit）＝セーブ

  • 変更に「ここまでやった」と名前をつけて記録すること
  • 1コミット＝1つの区切り（例：「ログイン画面を追加」）
  • メッセージを書くと、後から履歴が読める
ゲームのセーブ＋メモ。「何をしたセーブか」を一言つけるのがコツ。
用語 3

プッシュ / プル

push（プッシュ）

手元のコミットを GitHub へアップロードする。

pull（プル）

GitHub の最新を手元へダウンロードする。

チームで作業する前に pull（最新を取る）、作業が終わったら push（共有する）。
用語 4

ブランチ（branch）＝作業用の分身

  • 本番（main）を触らずに、別レーンで安全に作業する仕組み
  • 実験・新機能ごとに枝を分けて、失敗しても本番は無傷
  • できたら本番に合流させる（次のマージへ）
たとえ：清書（main）はそのままに、下書き用紙（ブランチ）で試す。良ければ清書に反映。
用語 5

マージ（merge）＝合流

  • ブランチの変更を、本番（main）に取り込むこと
  • 複数人の変更もここで1つにまとまる
  • ぶつかったら「コンフリクト」→ どちらを採用するか選ぶ
支流（ブランチ）が本流（main）に合流するイメージ。
用語 6

プルリクエスト（PR）＝合流の申請

  • 「このブランチをmainに入れていい？」とチームに提案する場
  • 変更点をみんなで見て、コメント・レビューできる
  • OKが出たらマージ。共同開発の心臓部
いきなり本番に入れず、「これ入れます、確認して」と一度みんなに見せる作法。
全体像

基本の流れ（これだけ覚えて帰る）

ブランチ作る→ 変更→ commit→ push→ PR→ merge
この6歩がGitHubの共同作業のすべての土台。今日はこれを1周体験します。
ハンズオン 準備

道具をそろえる

  • GitHubアカウント（作成済みでOK）
  • おすすめ：GitHub Desktop（コマンド不要のクリック操作アプリ）
  • 慣れたい人：ターミナル＋VS Code
今日は最短ルート。難しいコマンドは「困ったらAIに聞く」でOK。
ハンズオン ①

リポジトリを作る

  • GitHub右上の「＋」→ New repository
  • 名前を入れる（例：aircle-github-practice）
  • 「Add a README」にチェック → Create
これであなたの「プロジェクトの箱」がクラウドに完成。まだ中身は空でOK。
ハンズオン ②

手元に持ってくる（clone）

GitHub Desktop なら「Clone」ボタン一つ。コマンド派はこちら：

git clone https://github.com/<あなた>/aircle-github-practice.git
clone＝GitHubの箱を、そのまま自分のPCにコピーしてくること。
ハンズオン ③

変更して、セーブ（commit）

READMEに自己紹介を1行足してみよう。保存したら：

git add . git commit -m "READMEに自己紹介を追加"
add＝セーブするファイルを選ぶ／commit＝メモをつけてセーブ。Desktopならクリックだけ。
ハンズオン ④

GitHubへ送る（push）

git push
  • ブラウザでリポジトリを更新すると、変更が反映されている
  • 「クラウドに自分の作業が乗った」瞬間🎉
ここまでで「作る→セーブ→共有」の1往復を体験。おめでとうございます！
ハンズオン ⑤

ブランチ → プルリク体験

git switch -c my-first-branch git commit -am "変更" git push -u origin my-first-branch
  • GitHubに「Compare & pull request」ボタンが出る → 押す
  • 説明を書いて Create pull request → Merge
コツ

README はプロジェクトの顔

  • 何のプロジェクトか、を最初の3行で書く
  • 使い方・メンバー・リンクを箇条書きで
  • Markdown（# や - で書く軽い書式）で見やすく
訪問者が最初に読むページ。ここが丁寧だと「ちゃんとした団体」に見える。
共同作業

Issue と PR でチーム開発

Issue（イシュー）

「やること・バグ・アイデア」を書いておく付箋。担当も決められる。

Pull Request

変更を提案し、レビューしてから取り込む。会話が記録に残る。

Issueで「何をやるか」、PRで「やったものを確認して入れる」。この2つで回る。
活用

アークルでの 使い方アイデア

  • プロンプト集・AIツールのコードをチームで共有＆改善
  • 勉強会の資料・議事録をリポジトリに蓄積（ナレッジ化）
  • ハッカソン作品を置いて、そのまま就活ポートフォリオに
  • 役割分担してPRでレビューし合う練習
活用

GitHub Pages で無料公開

  • リポジトリのHTMLを、そのままWebサイトとして公開できる
  • Settings → Pages → ブランチを選ぶだけ
  • 作品やLPを世界に見せられる（例：このスライドも公開可）
「作る」だけで終わらず「公開して見せる」まで無料でいける。
つまずき対策

よくある詰まり＆解決

  • 「push できない」→ 先に pull して最新を取る
  • 「コンフリクト」→ 落ち着いて、残す方を選ぶだけ
  • 「コマンドが不安」→ 画面とエラーをそのままAIに貼って聞く
エラーは敵じゃない。メッセージをコピペしてAIに聞けば、たいてい解決します。
便利ツール

味方になるツール

GitHub Desktop

コマンド不要。クリックでcommit/push。初心者はまずこれ。

VS Code

編集＋Git操作が1画面で完結。拡張機能も豊富。

Claude Code

AIに「これやって」と頼むと、コードもGit操作も代行。

Student Pack

学生は有料機能が無料に。申請しておこう。

  • 自分のリポジトリを1つ作る（テーマは何でもOK）
  • READMEに自己紹介を書いて commit & push

小さく1周まわすのが上達の最短。まずは「触った」実績をつくろう。
