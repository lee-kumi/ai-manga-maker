# CMO Marketing Story For HTML Slides

HTML スライドの構成前に読む。目的は「きれいな資料」ではなく、聴衆が納得し、次の行動を取りやすい資料にすること。

## Strategy Gate

構成案を書く前に、次の4点を1文ずつで内部整理する。

| 観点 | 問い |
|---|---|
| Audience | 誰が、どんな前提知識・不安・期待を持って見るか |
| Desired Action | 見終わった後に何をしてほしいか |
| Core Promise | その人に何ができるようになる、または何が楽になるか |
| Proof | なぜ信じられるか。実績、比較、手順、事例、デモ、数字のどれで示すか |

この4点が曖昧なら、先に質問する。特に Desired Action がないデッキは、CTA もストーリーも弱くなる。

## Story Patterns

| 用途 | 推奨ストーリー |
|---|---|
| ウェビナー / セミナー | 共感できる現状 → 誤解の解除 → 仕組み → 具体例 → その場でできる手順 → CTA |
| 提案 / 営業 | 相手の現状 → 放置コスト → 方針 → 具体施策 → 体制・進行 → リスク対応 → 次アクション |
| ローンチ / 告知 | 変化の背景 → 新しい選択肢 → 誰に効くか → 体験・成果 → 参加/購入の導線 |
| 教育 / 講座 | 到達点 → 前提知識 → 実演/演習 → 失敗しやすい点 → 復習 → 次にやること |
| 採用 / 広報 | なぜ今この取り組みか → 独自性 → 仕事のリアル → 期待する人 → 応募/接点 |

## Slide Allocation

| ブロック | 目安 |
|---|---|
| 問題提起・共感 | 15-25% |
| 仕組み・解決策 | 25-35% |
| 具体例・証拠・デモ | 25-35% |
| 行動導線・CTA | 10-20% |

ウェビナーでは CTA を最低3回に分ける: なぜ今、具体的ステップ、最後のひと押し。

## Message Rules

- 各スライドの見出しはカテゴリ名ではなく主張文にする
- 「できること」「誰の何がどう変わるか」「現状との差分」を具体化する
- ローカルファイル名、リポジトリパス、参照ドキュメント一覧をスライドに載せない
- 専門語は、会議室で聞いて意味が取れる日本語に直す
- RACI、MVP、PdM、スコープ等を出す時は、同じスライド内で意味を添える
- 不要な括弧、脚注、注釈だらけの但し書きを減らす
- 煽りすぎない。危機感は放置コスト、比較、事例で示す
- CTA は「申込」「購入」だけでなく、相談、承認、次回MTG、学習継続も含めて設計する

## Visual Direction

- 抽象概念はカード羅列ではなく、フロー、マトリクス、Before/After、タイムライン、ファネルで見せる
- 数字があるなら大きな数字と比較軸を作る。小さな表だけで終わらせない
- 感情を動かすスライドは写真、事例、発言で現実感を出す
- 同じ訴求が続く時は、ステートメント、図解、対比、数字、手順をローテーションする
- Web 的にスカスカな綺麗さより、実務資料として判断材料が入っていることを優先する

## Quality Checklist

- [ ] Audience / Desired Action / Core Promise / Proof が整理されている
- [ ] スライド内に作業用パス・参照ファイル一覧を出していない
- [ ] 主要セクションに「できること」「変化」「差分」「証拠」が入っている
- [ ] 難語・略語に日本語の説明がある
- [ ] CTA が文脈上必要な位置にある
- [ ] テキスト主体スライドが続く場所は図解・対比・数字へ変換した
- [ ] HTML 実装後にコピー収まりと validator を確認した
