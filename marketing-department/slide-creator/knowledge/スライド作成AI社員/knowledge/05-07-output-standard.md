# 05-07-output-standard.md — セミナースライド制作の正解基準

このAI社員は、単にHTMLスライドを作る担当ではない。
セミナーの流れ、話者の信頼、実績提示、理論説明、例え話、証拠、クロージング、販売導線までを一体で設計し、HTMLデッキとして完成させる担当である。

## 1. 出力フォルダの標準

```text
output/archive/YYYY-MM-DD_event-slug/
├── brief.md
├── questions.md
├── story-plan.md
├── source-map.md
├── review-notes.md
├── assets/
├── slides/
│   └── index.html
└── screenshots/
    └── final/
```

`slides/index.html` だけ出して終わりにしない。
何を読み、何を採用し、どのテンプレートを使い、どこを修正したかまで残す。

## 2. 固定化するブロック

毎回のテーマが変わっても、次のブロックは固定資産として磨く。

| ブロック | 役割 | 毎回の扱い |
|---|---|---|
| 表紙 | イベントの期待値を一瞬で作る | 前回の強い表紙構造を踏襲し、タイトル・日付・メインビジュアルだけ差し替える |
| 自己紹介 | 誰が話すのかを納得させる | 固定スライドを使い回し、必要な実績だけ更新する |
| 実績 | この人の話を聞く理由を作る | 序盤に置く。数字は一次情報だけ使う |
| 目次/章扉 | 受講者の現在地を作る | ブランドカラー、ロゴ透かし、数字、強い短文で統一する |
| 問いかけ | 自分ごと化させる | 1回のプレゼンに2回以上入れる |
| 理論図解 | 仕組みを理解させる | 例え話の前に置く。まず構造を見せる |
| 例え話 | 腹落ちさせる | 内容に応じて変える。デパート固定ではない |
| 証拠壁 | 「本当にできる」を見せる | スクショ、動画、成果物、ロゴ、数字で見せる |
| クロージング | 商品・次回行動へつなぐ | 自社サービス案内や次CTAなど固定資産を使い、テーマに合わせて接続する |

## 3. 可変にするブロック

次はテーマごとに変える。

- セミナーの中心理論
- 具体例
- 例え話
- 最新実績
- 当日のオファー
- 証拠素材
- 次イベント導線

固定ブロックと可変ブロックを混ぜると、毎回ゼロから作り直しになり、品質が落ちる。

## 4. テンプレート抽象化ルール

参考デッキから盗むのは、文言ではなく次の要素。

- 余白
- 文字サイズの強弱
- 画像と文字の比率
- 章扉の作り方
- 問いかけの見せ方
- 実績の出し方
- 証拠スクショの並べ方
- クロージングの温度感

テンプレートライブラリは用途別に整理する。

| family | 用途 |
|---|---|
| cover | 表紙 |
| profile | 自己紹介 |
| proof | 実績・証拠 |
| question | 問いかけ |
| theory | 理論図解 |
| metaphor | 例え話 |
| comparison | 比較・レベル分け |
| proof_wall | 大量の成果物提示 |
| section_bridge | 章扉 |
| closing | 商品説明・CTA |

## 5. デザイン品質基準

- 文字だけのスライドを連発しない。
- 1スライド1メッセージは、1文だけにする意味ではない。伝える結論を1つに絞ること。
- タイトルは基本1行。ただし無理な1行詰め込みで読みにくいなら2行にする。
- 画像比率を壊さない。証拠スクショ、LP、YouTubeサムネ、動画は特に切り抜きすぎない。
- 章扉はブランドを固定する。毎回違う見た目にしない。
- ロゴ位置、フッター、左上装飾、中央下マークはページごとにズレない。
- 画像・動画の黒帯が多い場合は、枠ではなく比率と配置を見直す。
- 重要スライドはテンプレから選ぶ。勝手にチープな図を作らない。

## 6. ストーリー品質基準

セミナーは次の順で自然につなぐ。

1. 表紙で期待値を作る。
2. 自己紹介で「誰やねん」を消す。
3. 実績で話を聞く理由を作る。
4. 今日のテーマが便利機能紹介ではなく事業に効く土台だと伝える。
5. 受講者の現状課題を言語化する。
6. 理論で仕組みを見せる。
7. 証拠で「本当にできている」を見せる。
8. 例え話で腹落ちさせる。
9. 受講者に「自分はまだできていない」と気づかせる。
10. 商品・講座・次回導線へ接続する。

## 7. スクショQA

完成後は必ず全ページを画像化して見る。

チェック項目:

- [ ] 文字が親要素からはみ出していない
- [ ] 見出しが意図せず折れていない
- [ ] 画像比率が崩れていない
- [ ] スクショ/動画が見切れていない
- [ ] 同じ構成のスライドが連続しすぎていない
- [ ] 章扉のブランドルールが揃っている
- [ ] ロゴ位置が揃っている
- [ ] 文字だけのチープなスライドがない
- [ ] クロージングの熱量が落ちていない
- [ ] 最後のCTAが明確

## 証拠画像のトリミング指針（2026-07-07追記）

- `img/proof-*.png` 等の証拠スクショは、**余白（白地）が大きい場合は白カード `.card-hard` に入れて上寄せで見せる**か、事前に有効領域だけへトリミングする。原寸をそのまま貼って下半分が白地で破綻して見える状態はNG。
- 比率は壊さない（縦横比固定のままトリミング・拡縮のみ）。

## 表紙背景の標準（2026-07-07追記）

- 表紙の背景画像は `engine/07-seminar-style/img/seminar-cover-generic.png`（文字なし・黒×黄グラデ・左半分が文字用の余白）を標準にする。見本の `seminar-cover.png` はタイトル焼き込み済みサンプルのため、**別テーマの本番では使わない**。タイトル・日付はHTMLテキストで載せる（後から直せる状態を保つ）。
